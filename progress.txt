Bugs found and fixed during implementation (real, not hypothetical):
1. Prisma MongoDB connector requires relation-based updates for self-relation FK (`parent: {connect/disconnect}`), not the raw `parentId` scalar, on TodoUpdateInput. Fixed in app/api/todos/[id]/route.ts.
2. vitest.config.ts failed to load ("ESM file cannot be loaded by require") because vite-tsconfig-paths is ESM-only and the project has no "type":"module". Fixed by renaming to vitest.config.mts.
3. DnD rollback test was flaky/racey with an instantly-resolving mock fetch (assertion of the transient optimistic state sometimes ran after rollback already completed). Fixed by using a manually-controlled (deferred) fetch promise so the optimistic state is observed deterministically before forcing the rejection.
4. scripts/dev-with-mongo.ts: MongoMemoryReplSet with a *persistent* dbPath is unreliable — (a) an ungracefully-killed previous run leaves an orphaned mongod holding dbPath's lock file ("DBPathInUse" on next start), and (b) even after clearing that, replSetInitiate against a dbPath that already has replica-set config from the prior run causes a connection reset instead of completing init. Fixed by: killing the orphaned mongod matched by the exact PID recorded in mongod.lock, then wiping+recreating dbPath on every dev-server start (local dev data intentionally does not persist across `npm run dev` restarts — documented as a PRD criterion amendment on US-002). Also fixed a Windows `spawn EINVAL` when invoking the `next.cmd` shim without `shell:true`.
5. Found (not created) a `.env` file with what looks like real MongoDB Atlas credentials appearing in the project root mid-session (matches the user's email in the username). Not used anywhere in the app (code reads DATABASE_URL, not MONGODB_URI); left untouched; flagged to the user in chat.

Environment notes for whoever resumes this: no Docker, no local mongod binary, but npm registry and MongoDB's binary download server are reachable, so mongodb-memory-server works for both dev and test. `npm run dev` picks a free port if 3000+ are occupied by other processes on the machine (observed: user has several unrelated dev servers already running on this machine — do not assume port 3000).

[iteration 4] Architect re-review confirmed all 4 round-1 blockers resolved, but found ONE new blocker (present since iteration 2, missed in round 1 review, not a regression from the round-1 fixes): createTodoSchema.parentId was `.optional()` without `.nullable()`, so CreateTodoForm's `parentId: parentId || null` payload (sent on every submit when no parent is chosen) was rejected by its own schema with 400 -- meaning NO todo could be created from the UI unless a parent was explicitly picked, and YEARLY todos (which have no parent picker at all) could never be created from the UI. This was the single most central P0 path (docs/PRD.md 할 일 생성) and was broken.
Fixed:
- lib/validation.ts: createTodoSchema.parentId -> .nullable().optional(), matching updateTodoSchema. app/api/todos/route.ts POST: `!== undefined` -> `!= null` in both the parent-existence check and the `parent: {connect}` spread.
- Added tests/components/CreateTodoForm.test.tsx rendering the real CreateTodoForm against the real route handlers (the missing test class the reviewer identified: no test had ever driven the actual payload-building component) -- covers both "no parent selected" and "YEARLY has no parent picker at all".
- Found and fixed a real test-infra bug while adding that test: @testing-library/react's auto-cleanup-between-tests only registers when it detects a global `afterEach` (Vitest's `test.globals: true`), which this project doesn't enable, so render() output was leaking across tests in the same file. Added explicit `afterEach(cleanup)` to tests/setup/testing-library.ts.
- Also fixed the reviewer's promoted-to-required finding: the periodType edit added for US-005 (round 1) opened a UI-reachable path to silently orphan a child (change periodType on a still-parented todo -> child points at a now-wrong-level parent, drops out of that parent's ChildrenPanel/yearly-progress basis while parentId is still set). [id]/route.ts PATCH now returns 400 if periodType changes while parentId (existing or newly-set in the same request) is non-null, and rejects a todo being set as its own parent. TodoCard.tsx now surfaces updateTodo errors so this isn't a silent no-op in the UI.
